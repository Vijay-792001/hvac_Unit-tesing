- Purpose: Implements simple power and position LED control for an STM32F4-based board, mapping logical positions to five LEDs and managing a separate power LED; aligns with traced requirements SWE-REQ-021/022/023/024/025/026/027/029/044.
- Main functions:
  - StatusIndicator_Init: Configures GPIOC pins PC0–PC5 as push-pull outputs; turns power LED on (PC0 high) and clears all position LEDs (PC1–PC5 low).
  - StatusIndicator_Update(position_valid, logical_position): Clears all position LEDs, then lights exactly one LED if position_valid != 0 and logical_position ∈ [1..STATUS_INDICATOR_NUM]; logical_position 1 maps to PC1, …, 5 maps to PC5.
  - StatusIndicator_SetPowerLED(onoff): Sets or clears the power LED (PC0) based on onoff (1=on, 0=off).
- Key data/flows:
  - Static GPIO_InitTypeDef reused for initialization; all relevant pins configured in a single HAL_GPIO_Init call on GPIOC.
  - Position LED mapping via s_led_pos_pins[5] array; index uses logical_position - 1 with bounds guarded by runtime checks.
  - Update flow always resets all position LEDs before optionally setting one, ensuring one-hot display or all-off when invalid.
- Dependencies and interfaces:
  - Uses STM32 HAL (stm32f4xx_hal.h): HAL_GPIO_Init, HAL_GPIO_WritePin, GPIO types/macros (ports, pins, modes, pull, speed).
  - status_indicator.h expected to define STATUS_INDICATOR_NUM (must match array length, here 5) and public prototypes.
  - Hardware assumptions: LEDs are active-high; all LEDs wired to GPIOC pins PC0–PC5.
- Assumptions/constraints:
  - RCC clock enable for GPIOC is expected to be done elsewhere (not handled here).
  - STATUS_INDICATOR_NUM must equal 5 to avoid out-of-bounds access; code implicitly assumes this consistency.
  - Logical position 0 intentionally displays no green LED; any out-of-range position is ignored (all position LEDs remain off).
- Error handling/validation:
  - Minimal validation: checks position_valid and logical_position range; no error returns or logging.
  - No handling for HAL failures (HAL functions assumed to succeed).
- Notable behaviors/risks:
  - Non-atomic multi-LED updates; if called from concurrent contexts/ISRs without protection, may flicker or race.
  - Rewrites all position LEDs on every update; acceptable for low-frequency updates but could waste cycles if called often.
  - No debouncing or timing; purely immediate GPIO control.
- Configuration details:
  - GPIO mode: output push-pull, no pull resistors, low speed for all pins PC0–PC5.
