- Module: item; Source file path: c_file_path. Purpose: drive a single power LED and up to STATUS_INDICATOR_NUM position LEDs on STM32F4 using HAL GPIO; maps a 1-based logical position to a single “active” position LED and keeps the power LED independently controllable.
- Key dependencies: status_indicator.h (defines STATUS_INDICATOR_NUM and prototypes), stm32f4xx_hal.h (GPIO types/APIs), GPIOC port with pins 0–5. Uses HAL_GPIO_Init and HAL_GPIO_WritePin with push-pull, no-pull, low-speed config.
- Data/config: static GPIO_InitTypeDef GPIO_InitStruct; static const uint16_t s_led_pos_pins[STATUS_INDICATOR_NUM] = { GPIO_PIN_1 … GPIO_PIN_5 } mapping position index 1..N to pins PC1..PC5.
- StatusIndicator_Init(): configures PC0–PC5 as output; turns power LED (PC0) ON; turns all position LEDs (PC1–PC5) OFF.
- StatusIndicator_Update(position_valid, logical_position): first turns OFF all position LEDs; if position_valid != 0 and 1 <= logical_position <= STATUS_INDICATOR_NUM, turns ON exactly one LED at index logical_position - 1 (so position 1 -> PC1, …, position 5 -> PC5); position 0 or invalid -> no position LED lit.
- StatusIndicator_SetPowerLED(onoff): directly sets the power LED state (1=ON, 0=OFF) on PC0, independent of position LEDs.
- Control flow: simple, synchronous GPIO writes; update always clears all position LEDs before optionally lighting one, preventing multiple LEDs from staying on from prior states.
- Error handling/validation: bounds/checks only for logical_position and validity flag; no return values, assertions, or HAL error checks; assumes HAL is initialized and GPIOC clock enabled elsewhere.
- Notable assumptions/risks: STATUS_INDICATOR_NUM must match the initializer length (5) or compilation/behavior issues may occur (extra elements become 0, leading to Pin=0 writes); relies on fixed port C layout; no debouncing/timing; functions are not re-entrant/thread-safe if called concurrently without external synchronization.
